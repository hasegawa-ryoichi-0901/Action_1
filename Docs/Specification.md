# 仕様書

## 1. 文書概要

- プロジェクト名: `Temple Guardian`
- ジャンル: 短編3Dダークファンタジー・ボス討伐アクション
- 対応環境: `Windows PC`
- 開発エンジン: `Unity 6.0.4f1`
- 描画パイプライン: `URP`
- 想定プレイ時間: `15〜30分`
- 開発期間: `2026-07-01` 〜 `2027-06-30`

この文書は、企画要件を Unity 実装前提で具体化した開発用仕様書である。

## 2. 目的

本作の目的は、短時間で遊び切れる高密度なボス戦体験を提供することにある。

重視する体験は以下。

- 攻撃を見て回避する緊張感
- 敗因が理解できる納得感
- 少しずつ対応できるようになる上達感
- 小規模でも雰囲気のある神殿探索

本作はソウルライクの規模を目指さない。目指すのは、完成した短編アクションである。

## 5. プレイヤー仕様

### 5.1 基本操作

| 操作 | 内容 |
|---|---|
| 移動 | `WASD` または左スティックで移動 |
| 視点操作 | マウスまたは右スティックでカメラ操作 |
| 通常攻撃 | 近接攻撃を行う |
| 回避 | スタミナを消費して回避行動を行う |
| 回復 | 所持回数を消費してHPを回復する |
| ロックオン | 対象を捕捉し、戦闘時の視点維持を補助する |
| ポーズ | ポーズメニューを開く |

### 5.2 プレイヤーステータス

| 項目 | 内容 |
|---|---|
| HP | 0で死亡 |
| スタミナ | 攻撃、回避で消費し、時間経過で回復 |
| 攻撃力 | 与ダメージに影響 |
| 回復数 | 回復可能回数 |
| 無敵時間 | 回避中または被弾直後の一定時間に有効 |

### 5.3 行動ルール

- 攻撃中は即時に他行動へ遷移しない
- スタミナ不足時は攻撃と回避を発動できない
- 回避には短い無敵時間を持たせる
- 被弾時は短い硬直と無敵時間を与える
- 死亡時は最後のチェックポイントから再開する

## 6. 戦闘仕様

### 6.1 戦闘の成立条件

- プレイヤー攻撃が敵へ命中する
- 敵攻撃がプレイヤーへ命中する
- 双方がHPを持ち、0で戦闘不能になる
- 攻撃には予備動作、判定発生、硬直を持たせる
- ヒット時に最低限のSEとVFXを再生する

### 6.2 スタミナ仕様

- 通常攻撃で消費する
- 回避で消費する
- 移動中は回復してよい
- 攻撃中・回避中は回復停止または低下でよい
- 0付近では連続行動できない設計にする

### 6.3 ダメージ仕様

- ダメージは固定値ベースでよい
- 成長要素によりプレイヤー与ダメージは増加する
- 被弾時はノックバックまたは軽い怯みを発生させる
- 理不尽さを避けるため、敵攻撃前の予兆を明確にする

## 7. 敵仕様

### 7.1 敵共通仕様

- 待機、索敵、接近、攻撃、被弾、死亡の状態を持つ
- プレイヤーを一定距離で検知する
- 攻撃前に読み取れる予備動作を持つ
- 被弾時にリアクションする
- 死亡時に消滅または停止する

### 7.2 敵A

役割:
- 最も基本的な近接敵

仕様:
- プレイヤーへ接近する
- 単発近接攻撃を行う
- 予備動作は長めにする
- HPは低めに設定する

### 7.3 敵B

役割:
- 敵Aより対応判断を要求する敵

仕様:
- 一定距離を保とうとする
- 突進または中距離攻撃を行う
- 敵Aより攻撃タイミングをずらす
- HPまたは機動力を高めに設定する

## 8. ボス仕様

### 8.1 基本情報

| 項目 | 内容 |
|---|---|
| 名称 | 神殿の番人 |
| 戦闘場所 | 祭壇エリア |
| 想定戦闘時間 | 初見 `5〜10分`、慣れ後 `2〜4分` |
| 勝利条件 | ボスHPを0にする |
| 敗北条件 | プレイヤーHPが0になる |

### 8.2 行動仕様

最低限、以下の攻撃カテゴリを持たせる。

- 横薙ぎ
- 叩きつけ
- 突進

余力があれば以下を追加する。

- 範囲攻撃
- フェーズ2専用攻撃

### 8.3 フェーズ仕様

- フェーズ1で基本攻撃を使用する
- `HP 50%以下` でフェーズ2へ移行する
- フェーズ2では攻撃速度上昇または追加攻撃を1つ付与する

### 8.4 品質要件

- 全攻撃に見て分かる予備動作があること
- 被弾理由がプレイヤーに伝わること
- 回避可能なタイミングが存在すること
- カメラが極端に見づらくならないこと

## 9. マップ仕様

### 9.1 エリア構成

| エリア | 内容 |
|---|---|
| 神殿入口 | 導入、操作確認 |
| 外庭 | 敵Aとの基本戦闘 |
| 崩れた回廊 | 探索、素材配置 |
| 祈りの間 | 強化、チェックポイント |
| 祭壇 | ボス戦エリア |

### 9.2 レベルデザイン方針

- 一本道寄りで迷いにくくする
- 分岐は最大 `2つ` までに抑える
- ボス前にチェックポイントを置く
- ボス前に安全地帯または回復補充導線を置く
- 雰囲気目的だけの不要部屋は作らない

## 10. 成長・強化仕様

### 10.1 強化項目

| 項目 | 最大段階 | 効果 |
|---|---:|---|
| HP強化 | 2 | 最大HP上昇 |
| 攻撃力強化 | 2 | 与ダメージ上昇 |
| 回復数強化 | 1 | 回復可能回数増加 |

### 10.2 強化素材

| 項目 | 内容 |
|---|---|

| 使用場所 | 祈りの間 |
| 設計方針 | 周回稼ぎ不要、短編内で完結 |

## 12. セーブ仕様

保存対象は以下とする。

- 現在のチェックポイント
- HP強化段階
- 攻撃力強化段階
- 回復数強化段階

## 15. 受け入れ基準

### 15.1 MVP受け入れ基準

- タイトルからゲーム開始できる
- プレイヤーが移動、攻撃、回避できる
- 通常敵を倒せる
- ボスと戦える
- ボス撃破でクリアになる
- 死亡時にリトライできる
- `15分以上` の通しプレイが成立する
- Windowsビルドで最後まで遊べる

### 15.2 品質受け入れ基準

- ボス攻撃前モーションが分かる
- 被弾理由がプレイヤーに伝わる
- 操作遅延が気にならない
- カメラが壁に大きく埋まらない
- UIが最低限読める
- SEとVFXで命中感がある

## 17. 仕様変更ルール

- MVP対象外の追加案は `Docs/Backlog.md` で管理する
- 仕様変更時は、実装前に `スコープ影響` と `工数影響` を確認する
- 進行遅延時は、見た目や追加演出から削る
- ボス戦の可読性とプレイヤー操作品質は削らない
