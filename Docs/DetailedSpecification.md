# 詳細仕様書

## 1. 文書位置づけ

この文書は [Specification.md](Specification.md) を実装判断レベルまで具体化した詳細仕様である。

目的は以下。

- 実装単位を明確にする
- システム間の依存関係を整理する
- MVP で必要な挙動を曖昧さなく定義する

## 2. システム構成

本作は以下のシステムで構成する。

1. ブート・シーン遷移
2. プレイヤー入力
3. プレイヤー移動・カメラ
4. プレイヤー戦闘
5. 敵共通AI
6. ボスAI
7. マップ・進行制御
8. 成長・強化
9. UI
10. セーブ
11. 音・演出

## 3. ブート・シーン遷移詳細

### 3.1 シーン責務

| シーン | 責務 |
|---|---|
| `Title` | タイトル表示、ゲーム開始、終了 |
| `Main` | 探索、戦闘、UI、セーブ対象状態の保持 |
| `Reload` | シーン再初期化、リトライ補助 |

### 3.2 起動フロー

1. アプリ起動時に `Title` を開く
2. `Start` 選択で `Main` をロードする
3. `Retry` 選択時は必要に応じて `Reload` を経由して `Main` を再初期化する
4. `Title` 復帰時は戦闘状態と一時状態を破棄する

### 3.3 要件

- タイトルから `10秒以内` に操作可能であること
- リトライ時に不要な状態を引き継がないこと
- ボス撃破後は必ずクリア画面へ遷移すること

## 4. プレイヤー入力詳細

### 4.1 入力マッピング

| 入力 | キーボード/マウス | ゲームパッド |
|---|---|---|
| 移動 | `WASD` | 左スティック |
| 視点 | マウス移動 | 右スティック |
| 攻撃 | 左クリック | `X / Square` 相当 |
| 回避 | `Space` | `A / Cross` 相当 |
| 回復 | `R` | `Y / Triangle` 相当 |
| ロックオン | `Q` | `R3` または `LB` 相当 |
| ポーズ | `Esc` | `Start` 相当 |

### 4.2 入力ルール

- 同時入力時は状態に応じて優先度を持つ
- 攻撃中の回避キャンセル可否はアニメーション長に応じて調整する
- UI表示中はプレイヤー移動入力を無効化する

### 4.3 入力優先度

優先度の基本順は以下。

1. 死亡
2. 被弾
3. ポーズ
4. 回避
5. 攻撃
6. 回復
7. 移動

## 5. プレイヤー移動・カメラ詳細

### 5.1 移動仕様

- 移動はカメラ正面基準で方向決定する
- 移動速度は通常時固定値でよい
- ロックオン中は対象方向を意識した旋回を行う
- 段差・壁衝突時に過度な引っかかりを出さない

### 5.2 カメラ仕様

- 通常時は三人称追従カメラ
- ロックオン時はプレイヤーと対象が画面に入るよう補正する
- 壁に近い場合はカメラ距離を短縮する
- 狭所ではカメラ埋まりを極力防ぐ

### 5.3 ロックオン仕様

- 一定距離以内の敵を対象候補にする
- カメラ前方の敵を優先する
- 対象死亡時は自動解除する
- 対象が距離外へ出たら解除してよい

## 6. プレイヤー戦闘詳細

### 6.1 状態一覧

| 状態 | 内容 |
|---|---|
| Idle | 待機 |
| Move | 移動 |
| Attack | 通常攻撃中 |
| Dodge | 回避中 |
| Heal | 回復中 |
| Hit | 被弾中 |
| Dead | 死亡中 |

### 6.2 通常攻撃仕様

- 攻撃は単発コンボなしでも可
- 前方近距離にヒット判定を出す
- 判定発生は予備動作後に1回だけでよい
- 攻撃後は短い後隙を持たせる

### 6.3 回避仕様

- 回避発動時にスタミナを消費する
- 回避中の一定フレームは無敵にする
- 無敵終了後は着地硬直または回避後硬直を入れる

### 6.4 回復仕様

- 回復入力で即時にHPを戻さず、短い使用動作を挟む
- 使用完了時にHPを回復する
- 所持回数が0の場合は発動しない

### 6.5 被弾・死亡仕様

- 被弾時はダメージ適用後に短時間無敵を付与する
- HPが0以下になったら `Dead` へ遷移する
- 死亡後はゲームオーバーUIまたはチェックポイント復帰導線を出す

## 7. スタミナ詳細

### 7.1 消費対象

- 通常攻撃
- 回避

### 7.2 回復ルール

- 非行動時に自動回復する
- 被弾中は回復停止してよい
- 回復速度は速すぎず遅すぎない中間設定とする

### 7.3 UI反映

- 現在値をバー表示する
- 行動不能時はプレイヤーが理由を理解できる見た目にする

## 8. 敵共通AI詳細

### 8.1 敵状態

| 状態 | 内容 |
|---|---|
| Idle | 待機 |
| Chase | プレイヤー追跡 |
| Attack | 攻撃 |
| Cooldown | 攻撃後硬直 |
| Hit | 被弾 |
| Dead | 死亡 |

### 8.2 共通ルール

- 索敵距離内でプレイヤーを認識する
- 攻撃距離まで接近してから攻撃する
- 攻撃前に明確な予備動作を置く
- 被弾時に状態遷移できる

## 9. 敵A詳細

### 9.1 設計意図

- 最初に戦う基礎敵
- プレイヤーに回避と攻撃差し込みを学ばせる

### 9.2 行動

- 直線的に接近
- 単発近接攻撃
- 攻撃後に大きめの隙

### 9.3 調整方針

- HPは低め
- 攻撃発生は遅め
- ダメージは中程度以下

## 10. 敵B詳細

### 10.1 設計意図

- プレイヤーに距離管理を要求する敵

### 10.2 行動

- 一定距離で様子を見る
- 突進または中距離攻撃
- 攻撃タイミングを敵Aより遅らせる

### 10.3 調整方針

- 敵Aより討伐に時間がかかる
- 予備動作は読めるが、油断すると被弾する

## 11. ボス詳細

### 11.1 ボス状態

| 状態 | 内容 |
|---|---|
| Intro | 登場演出 |
| Idle | 様子見 |
| Approach | 間合い調整 |
| Attack1 | 横薙ぎ |
| Attack2 | 叩きつけ |
| Attack3 | 突進 |
| PhaseShift | フェーズ移行 |
| Phase2Attack | フェーズ2専用 |
| Hit | 被弾 |
| Dead | 撃破 |

### 11.2 行動選択

- プレイヤーとの距離で候補行動を切り替える
- 近距離では横薙ぎ、叩きつけを優先する
- 中距離では突進を含める
- フェーズ2では1つだけ追加行動を解禁する

### 11.3 登場演出

- ボスエリア侵入で開始する
- プレイヤー操作を短時間制限してもよい
- 演出は長すぎず、再戦時は短縮またはスキップできると望ましい

### 11.4 撃破演出

- ボスHP 0到達で攻撃を停止する
- 撃破演出後にクリアUIを表示する
- 必要ならボス撃破フラグを保存する

## 12. マップ・進行制御詳細

### 12.1 進行構造

- 一本道寄りの進行
- 小規模探索分岐を最大2箇所まで許容
- ボス前に必ず休憩地点を置く

### 12.2 チェックポイント

- 到達時に現在進行を保存する
- 死亡時の復帰地点になる
- 必要であればHP、回復数を復元する

### 12.3 進行フラグ

- ボス戦開始済み
- ボス撃破済み
- 強化開放済み
- チェックポイント到達済み

## 13. 成長・強化詳細

### 13.1 強化UI要件

- 強化可能な項目一覧を表示する
- 必要素材数を表示する
- 強化後の段階を表示する

### 13.2 強化ルール

- 上限段階を超える強化は不可
- 素材不足時は決定不可
- 強化結果は即セーブ対象に反映する

## 14. UI詳細

### 14.1 HUD

- 左上または左下にHPとスタミナを表示する
- 回復数は視認しやすい位置に表示する
- ロックオン中は対象マーカーを表示する

### 14.2 ボスUI

- ボス戦開始時にボスHPバーを表示する
- ボス撃破時に非表示へ遷移する

### 14.3 画面遷移UI

- ポーズはゲーム進行を停止する
- ゲームオーバーは `Retry` と `Title` を表示する
- クリアでは `Clear` とプレイ時間を表示する

## 15. セーブ詳細

### 15.1 保存項目

- チェックポイントID
- 強化段階
- 素材所持数
- ボス撃破状態
- 最終プレイ状態の最小限情報

### 15.2 保存タイミング

- チェックポイント到達時
- 強化実行時
- ボス撃破時

### 15.3 ロード方針

- 起動時またはゲーム開始時に最新状態を読む
- クリア後の再開挙動は別途簡易化してよい

## 16. 音・演出詳細

### 16.1 必須SE

- 攻撃ヒット
- プレイヤー被弾
- 回避
- 回復
- 決定
- ボス登場
- ボス撃破

### 16.2 必須VFX

- 攻撃ヒット
- 回復
- ボス攻撃強調
- 撃破時の簡易消散または停止演出

## 17. デバッグ要件

開発中は最低限以下を確認できる状態が望ましい。

- プレイヤーHP
- スタミナ
- 敵HP
- ボスHP
- 現在ステート
- チェックポイントID

## 18. 受け入れ判定詳細

### 18.1 機能面

- 全シーン遷移が止まらない
- プレイヤー基本操作が途切れない
- 通常敵2種とボス1体が成立する
- セーブと復帰が破綻しない

### 18.2 品質面

- ボス全攻撃に読める前兆がある
- 少なくとも初見で「なぜ負けたか」が理解できる
- カメラ事故が頻発しない
- 通しプレイで進行不能が出ない
